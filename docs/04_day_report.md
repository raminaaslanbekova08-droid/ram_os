 2. Описание решений, которые были приняты

 2.1. Почему таблицы создаются в определённом порядке
Таблицы создаются строго с учетом зависимостей. Сначала идут справочники, которые ни на кого не ссылаются (`roles`, `sizes`, `products`). Затем создаются таблицы, ссылающиеся на справочники (`users` ссылается на `roles`, `stock_items` ссылается на `products` и `sizes`). В конце создаются транзакционные таблицы (`orders`, `order_items`). Если нарушить этот порядок, SQLite выдаст ошибку, так как внешний ключ не может ссылаться на несуществующую таблицу.

 2.2. Почему для заказов выбрана стратегия RESTRICT, а для состава заказа — CASCADE
*   **ON DELETE RESTRICT** используется для защиты важных данных. Например, нельзя удалить пользователя (`users`), если у него есть заказы (`orders`). Нельзя удалить товарную позицию (`stock_items`), если она уже добавлена в какой-то заказ (`order_items`). Это сохраняет историю и целостность бизнес-данных.
*   **ON DELETE CASCADE** используется для зависимых сущностей. При удалении заказа (`orders`) все его позиции в составе (`order_items`) удаляются автоматически. Без самого заказа эти строки не имеют смысла и являются «мусором» в базе.

 2.3. Почему размер обуви имеет тип REAL
Размер обуви не всегда является целым числом. Встречаются размеры с половиной (например, 36.5 или 42.5). Использование типа `INTEGER` привело бы к потере данных или ошибкам при вставке, поэтому выбран тип `REAL` (число с плавающей точкой).

 2.4. Почему дата заказа хранится как TEXT
В SQLite нет отдельного специализированного типа данных для даты (как `DATE` в других СУБД). Стандартом де-факто является хранение дат в виде строк в формате ISO 8601 (`YYYY-MM-DD`). Это позволяет корректно сортировать даты и использовать встроенные функции дат SQLite. Использовать для этого `DEFAULT date('now')` в определении таблицы нельзя, так как `DEFAULT` требует константу, поэтому дата передается явно из Python-кода при вставке.

 2.5. Какие индексы созданы и почему
Созданы следующие индексы (команда `CREATE INDEX`):
*   На все внешние ключи: `users.role_id`, `orders.user_id`, `stock_items.product_id`, `stock_items.size_id`, `order_items.order_id`, `order_items.stock_item_id`. Это значительно ускоряет операции `JOIN`.
*   На поля для фильтрации и сортировки: `orders.order_date` (ускоряет сортировку истории заказов) и `products.category` (ускоряет фильтрацию каталога).
Индексы занимают место и немного замедляют `INSERT`, поэтому проиндексированы только нужные поля, а не вся таблица целиком.
