 Сущности, атрибуты и связи

 1. Функциональные требования (своими словами)
1. В каталоге должно храниться актуальное количество доступных для заказа товарных позиций (сочетаний модель-размер).
2. Для каждой модели товара должно храниться изображение.
3. Пользователь должен иметь возможность выбирать одну или несколько пар обуви из каталога.
4. В интерфейсе должен быть доступен просмотр списка заказов (дата, ФИО клиента).
5. Должно быть реализовано управление заказами.

 2. Роли пользователей и их права
*   **Неавторизованный пользователь:** Просмотр каталога (без фильтрации, сортировки, поиска).
*   **Авторизованный пользователь:** Просмотр каталога (с фильтрацией, сортировкой, поиском), оформление заказов (добавление/удаление позиций, изменение количества).
*   **Менеджер:** Всё, что авторизованный пользователь + просмотр заказов, состава заказа, добавление новых заказов и удаление существующих.
*   **Администратор:** Всё, что менеджер + редактирование заказов.

 3. Различие пользователей при входе
Система различает пользователей по логину. Пароль не требуется. Поле `login` должно быть уникальным (UNIQUE). Если два пользователя получат одинаковый логин, система не сможет однозначно определить, кто именно вошел, что приведет к ошибкам прав доступа. На уровне БД это предотвращается ограничением UNIQUE.

 4. Данные о товаре для фильтрации, сортировки и поиска
*   **Фильтрация:** по категории и подкатегории.
*   **Сортировка:** по цене и наименованию.
*   **Поиск:** по наименованию и производителю.
Для ускорения поиска по этим полям потребуются индексы.

 5. Сущности и атрибуты

 Сущность: Роль (roles)
*   `role_id` (PK) - числовой идентификатор
*   `role_name` - название роли (Уникальное, обязательное)

 Сущность: Пользователь (users)
*   `user_id` (PK) - числовой идентификатор
*   `last_name` - фамилия (Обязательное)
*   `first_name` - имя (Обязательное)
*   `middle_name` - отчество (Необязательное)
*   `login` - логин (Уникальное, обязательное)
*   `role_id` (FK) - ссылка на роль (Обязательное)

 Сущность: Товар (products)
*   `product_id` (PK) - числовой идентификатор
*   `category` - категория (Обязательное)
*   `subcategory` - подкатегория (Обязательное)
*   `manufacturer` - производство/производитель (Обязательное)
*   `name` - наименование (Обязательное)
*   `image_path` - путь к изображению (Необязательное)
*   `composition` - состав (Необязательное)
*   `description` - описание (Необязательное)
*   `price` - цена (Обязательное)

 Сущность: Размер (sizes)
*   `size_id` (PK) - числовой идентификатор
*   `size_value` - значение размера (Обязательное, уникальное)

 Сущность: Товарная позиция (stock_items)
*   `stock_item_id` (PK) - числовой идентификатор
*   `product_id` (FK) - ссылка на товар (Обязательное)
*   `size_id` (FK) - ссылка на размер (Обязательное)
*   `available_quantity` - доступное количество (Обязательное, по умолчанию 0)

 Сущность: Заказ (orders)
*   `order_id` (PK) - числовой идентификатор
*   `order_date` - дата заказа (Обязательное, по умолчанию текущая дата)
*   `user_id` (FK) - ссылка на пользователя (Обязательное)

 Сущность: Состав заказа (order_items)
*   `order_item_id` (PK) - числовой идентификатор
*   `order_id` (FK) - ссылка на заказ (Обязательное)
*   `stock_item_id` (FK) - ссылка на товарную позицию (Обязательное)
*   `quantity` - количество (Обязательное)
*   `price_at_purchase` - цена на момент оформления (Обязательное)

 6. Ограничения атрибутов
*   **Обязательные (NOT NULL):** ФИО (кроме отчества), логин, цена, наименование, категория, подкатегория, производитель, количество, дата заказа.
*   **Необязательные (NULL):** Отчество пользователя, описание товара, состав, путь к изображению.
*   **Уникальные (UNIQUE):** Логин пользователя, название роли, значение размера.
*   **По умолчанию (DEFAULT):** Дата заказа = текущая дата, доступное количество = 0.
  
   7. Связи между сущностями
1.  **roles - users (1:N):** Одна роль может быть у многих пользователей. Один пользователь имеет только одну роль.
2.  **users - orders (1:N):** Один пользователь может оформить много заказов. Один заказ принадлежит только одному пользователю.
3.  **orders - order_items (1:N):** Один заказ содержит много товарных позиций. Одна позиция принадлежит только одному заказу.
4.  **products - stock_items (1:N):** Один товар (модель) может иметь много размеров (товарных позиций). Одна товарная позиция относится к одному товару.
5.  **sizes - stock_items (1:N):** Один размер может быть у многих товаров. Одна товарная позиция имеет только один размер.
6.  **stock_items - order_items (1:N):** Одна товарная позиция может входить во много заказов. Одна запись состава заказа относится к одной товарной позиции.

 8. Почему товарная позиция — отдельная сущность?
Если хранить размеры и количества в одной строке товара, получится несколько значений в одной ячейке (нарушение 1НФ). Кроме того, у одной модели может быть много размеров, и для каждого размера свое количество на складе. Без отдельной таблицы позиций не обойтись.

 9. Ограничения целостности
*   При удалении заказа должны удаляться все его позиции (ON DELETE CASCADE для order_items).
*   При удалении товара нельзя удалять позиции, которые уже вошли в заказы (ON DELETE RESTRICT для stock_items).
*   При удалении пользователя нельзя удалять его заказы (ON DELETE RESTRICT для orders).
