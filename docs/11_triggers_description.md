 Отчёт по Дню 11. Триггеры и аудит

 1. Какие триггеры созданы и для чего они нужны

В ходе работы было создано 6 триггеров, которые автоматизируют бизнес-логику и ведут аудит изменений:

1. **`trg_products_price_audit`** (`AFTER UPDATE OF price ON products`)
   * **Назначение:** Аудит изменения цен. Если кто-то меняет цену товара, триггер записывает старую и новую цену в таблицу `audit_log`. Условие `WHEN OLD.price <> NEW.price` защищает от ложных срабатываний (если цена не изменилась).
2. **`trg_orders_delete_audit`** (`AFTER DELETE ON orders`)
   * **Назначение:** Логирование удаления заказов. Записывает ID удаленного заказа в `audit_log`. Поле `record_id` заполняется из `OLD.order_id`.
3. **`trg_users_updated_at`** (`AFTER UPDATE ON users`)
   * **Назначение:** Автоматическое обновление поля `updated_at`. При любом изменении данных пользователя триггер устанавливает текущую дату и время.
4. **`trg_order_items_stock`** (`AFTER INSERT ON order_items`)
   * **Назначение:** Бизнес-логика списания остатков. Когда в заказ добавляется товар, триггер автоматически вычитает его количество из таблицы `stock_items` (поле `quantity_available`).
5. **`trg_users_no_delete_with_orders`** (`BEFORE DELETE ON users`)
   * **Назначение:** Защита данных. Запрещает удаление пользователя, если у него есть активные заказы, через `RAISE(ABORT)`.
6. **`trg_stock_no_negative_insert`** (`BEFORE INSERT ON stock_items`)
   * **Назначение:** Валидация данных. Запрещает добавление на склад товара с отрицательным количеством (`quantity_available < 0`).

 2. Разница между BEFORE и AFTER триггерами

* **BEFORE** срабатывает **до** применения изменения к таблице. Его используют, когда нужно проверить данные и, возможно, **отменить операцию** (через `RAISE(ABORT)`) или изменить данные до их сохранения. Пример: триггеры `trg_users_no_delete_with_orders` и `trg_stock_no_negative_insert`.
* **AFTER** срабатывает **после** того, как изменение уже применено. Его используют для **аудита** (логирования), так как старая и новая строки уже точно сформированы, или для обновления связанных таблиц. Пример: аудит цен и списание остатков.

 3. Как используются OLD и NEW

Внутри триггеров SQLite предоставляет две виртуальные таблицы:
* **`NEW`** — содержит данные строки **после** изменения (доступна в `INSERT` и `UPDATE`).
* **`OLD`** — содержит данные строки **до** изменения (доступна в `UPDATE` и `DELETE`).

**Примеры использования в моей работе:**
* При изменении цены: `OLD.price` (было) и `NEW.price` (стало).
* При списании остатков: `NEW.stock_item_id` и `NEW.quantity` берутся из только что добавленной строки `order_items`.
* При защите от удаления: `OLD.user_id` берется из строки, которую пытаются удалить.

 5. Как работает защита от удаления пользователя с заказами

Защита реализована через триггер **`BEFORE DELETE ON users`**. 
Перед тем как удалить пользователя, SQLite проверяет условие `WHEN EXISTS (SELECT 1 FROM orders WHERE user_id = OLD.user_id)`. Если у пользователя есть хотя бы один заказ, срабатывает команда `SELECT RAISE(ABORT, 'Нельзя удалить...');`. Это прерывает выполнение `DELETE`, транзакция откатывается, а Python-скрипт ловит ошибку `sqlite3.IntegrityError`.

 Ответы на вопросы для самопроверки

1. **В чем главное отличие триггера от процедуры или функции?**
   Триггер привязан к событию (`INSERT`, `UPDATE`, `DELETE`) и срабатывает автоматически. Его нельзя вызвать вручную. Процедуры и функции вызываются явно по имени.
2. **Почему в SQLite внутри триггера нельзя использовать сложный процедурный язык?**
   SQLite — встраиваемая БД, спроектированная для легкости и переносимости. Добавление полноценного процедурного языка (как PL/pgSQL в PostgreSQL) усложнило бы архитектуру и замедлило работу. Сложная логика выносится в Python/приложение.
3. **В чем разница между триггерами BEFORE и AFTER? Приведите пример, когда нужен именно BEFORE.**
   `BEFORE` — до применения изменений (можно отменить операцию). `AFTER` — после. `BEFORE` нужен, когда мы хотим заблокировать действие: например, запретить удаление пользователя, у которого есть заказы.
4. **Что произойдет, если в триггере AFTER UPDATE не использовать условие WHEN OLD.price != NEW.price?**
   Триггер будет срабатывать при **любом** обновлении строки (даже если поменяли только название товара, а цена осталась прежней). Таблица аудита будет забиваться мусорными записями.
5. **Для чего нужны виртуальные таблицы OLD и NEW?**
   Это ссылки на строку до и после изменения. Они позволяют сравнивать старые и новые значения (например, `OLD.price` и `NEW.price`).
6. **Почему в триггере на событие DELETE нельзя обратиться к NEW?**
   Потому что при удалении строки «новой» версии не существует. Есть только старая (`OLD`).
7. **Как заставить триггер прервать выполнение операции (вызвать ошибку) в SQLite?**
   Использовать команду `SELECT RAISE(ABORT, 'Текст ошибки');`.
8. **Зачем нужна таблица audit_log и какие поля в ней должны быть?**
   Для отслеживания истории изменений и безопасности. Поля: `log_id` (PK), `table_name` (таблица), `operation` (тип операции), `record_id` (ID измененной строки), `old_value`/`new_value` (старые/новые данные), `changed_at` (время).
9. **Как триггер может автоматически обновить остатки на складе при покупке товара?**
   Триггер `AFTER INSERT ON order_items` выполняет `UPDATE stock_items SET quantity_available = quantity_available - NEW.quantity WHERE stock_item_id = NEW.stock_item_id`.
10. **Что произойдет, если удалить таблицу, на которую был привязан триггер?**
    Триггер удалится автоматически. На следующий день он не сработает, так как его больше не существует (он привязан к таблице).
