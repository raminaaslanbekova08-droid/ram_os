 Отчёт по Дню 12. Администрирование базы данных SQLite

 1. Как в SQLite реализуются роли и права
В отличие от серверных СУБД (PostgreSQL, MySQL), в SQLite нет встроенных пользователей и паролей. Разграничение доступа реализуется на уровне приложения (Python-кода). 
В базе данных созданы таблицы `users` и `roles`, связанные внешним ключом. В Python-коде создан словарь `PERMISSIONS`, который строго определяет, какие SQL-команды разрешены каждой роли. Перед выполнением опасного запроса (например, `DELETE`) приложение вызывает функцию `check_permission()`, которая проверяет, имеет ли текущий пользователь право на это действие.

 2. Результаты тестирования функции check_permission
Были протестированы пользователи с разными ролями:
* **Пользователь с ролью `reader`:** Запрос на `DELETE` вернул `False` (запрещено). Запрос на `SELECT` вернул `True` (разрешено).
* **Пользователь с ролью `admin_db`:** Запрос на `DELETE` вернул `True` (разрешено).
Это доказывает, что система корректно разграничивает права доступа на основе ролей.

 3. Способы резервного копирования
Были реализованы два способа:
1. **`shutil.copy2` (простой):** Просто копирует файл. Плюс: работает быстро. Минус: если в момент копирования кто-то пишет в базу, копия может оказаться «битой».
2. **`sqlite3.backup()` (безопасный):** Использует встроенный API SQLite для создания снимка. Плюс: гарантирует целостность данных даже при активных транзакциях, так как учитывает блокировки.

 4. Результаты проверки PRAGMA integrity_check
При выполнении команды `PRAGMA integrity_check;` база данных вернула строку `"ok"`. Это означает, что внутренняя структура файла базы данных не имеет битых страниц и ошибок.

 5. Пошаговый сценарий восстановления базы
1. Сделан бэкап базы в папку `db/backups/`.
2. Через SQLite Viewer или Python из базы были удалены все заказы (`DELETE FROM orders`), имитируя сбой.
3. Запущена функция `restore()`, которая скопировала файл бэкапа обратно на место `db/shoe_store.sqlite`.
4. После проверки базы через SQLite Viewer — все заказы оказались на месте, восстановление прошло успешно.
